# Предрегистрация: новая страница оформления заказа

Документ фиксируется до запуска эксперимента. Изменения после запуска требуют новой версии документа с датой и причиной.

## 1. Гипотеза и бизнес-вопрос

Бизнес-вопрос: окупит ли новая версия страницы оформления заказа стоимость внедрения и поддержки за 12 месяцев.

Гипотеза: новая страница повышает конверсию пользователя в покупку за 7 дней после назначения.

- H0: конверсия в тесте равна конверсии в контроле.
- H1: конверсии различаются (двусторонний тест).

## 2. Вводные

| Параметр | Значение |
|---|---|
| Трафик | 6000 новых пользователей в день, все в эксперименте |
| Сплит | 50/50 |
| Базовая конверсия за 7 дней | 10% |
| Средний чек | 2500 ₽ |
| Валовая маржа | 30% выручки |
| Внедрение | 4 млн ₽ разово + 2 млн ₽ поддержка в год |
| Горизонт оценки | 12 месяцев |
| alpha | 0.05, двусторонний |
| power | 0.8 |
| MDE | 0.5 п.п. абсолютных (10% → 10.5%) |

## 3. Единица рандомизации

Пользователь. Назначение в группу детерминировано по идентификатору пользователя и не меняется между сессиями.

Не событие и не сессия, потому что:

- один пользователь видел бы обе версии, эффекты смешиваются;
- наблюдения внутри пользователя зависимы, стандартные ошибки занижаются, ложноположительных результатов больше номинальных 5%;
- решение принимается о пользователе и выручке с пользователя, единица анализа должна совпадать с единицей рандомизации.

## 4. Основная метрика

Конверсия пользователя в покупку за 7 дней после назначения: доля пользователей, сделавших хотя бы одну покупку в окне `[назначение, назначение + 7 дней)`.

Окно полное у всех: в анализ входят только пользователи, назначенные не позже чем за 7 дней до даты выгрузки. Набор пользователей идёт 21 день, анализ — после закрытия окна последней когорты (день 28).

Тест: z-тест для разницы двух долей, 95% доверительный интервал для разницы.

## 5. Вторичные метрики

| Метрика | Определение | Тест |
|---|---|---|
| ARPU за 7 дней | выручка за 7 дней / все назначенные пользователи | t-тест Уэлча |
| Средний чек | выручка / число заказов у покупателей | t-тест Уэлча (bootstrap по пользователям при сильной асимметрии) |
| Доля дошедших до корзины | пользователи с событием корзины / назначенные | z-тест долей |
| Доля дошедших до оплаты | пользователи с событием оплаты / назначенные | z-тест долей |

Поправка на множественность: Холм по четырём вторичным метрикам, FWER 0.05. Средний чек считается только по покупателям, поэтому его сравнение не рандомизировано и интерпретируется осторожно.

## 6. Guardrail-метрики

- Доля возвратов: заказы с возвратом / заказы.
- Время загрузки страницы оформления: p50 и p95 по пользователю.

Ухудшение — значимое изменение в худшую сторону на уровне 0.05, односторонний тест.

## 7. Размер выборки и длительность

Расчёт: `make design` (`scripts/design.py`).

| Величина | Значение |
|---|---|
| n на группу, нормальная аппроксимация без пула | 57 760 |
| n на группу, statsmodels (NormalIndPower, h Коэна) | 57 756 (−0.01%) |
| n на группу, итог | 57 760 |
| Длительность | 19.25 дня → 21 день (3 полные недели) |
| Пользователей всего | 126 000, по 63 000 в группе |

Округление до целых недель убирает перекос по дням недели. Фактическая мощность при 63 000 в группе для MDE 0.5 п.п. — 83%, достижимый MDE при мощности 80% — 0.47 п.п.

## 8. Правила остановки

- Фиксированный горизонт: 21 день набора + 7 дней окна.
- Один финальный анализ. Промежуточные просмотры основной метрики для решения не используются.
- Досрочная остановка по эффективности запрещена.
- Досрочная остановка разрешена только при:
  - SRM: хи-квадрат по числу пользователей в группах, p < 0.001;
  - техническом сбое (ошибки назначения, потеря событий, недоступность страницы);
  - значимом ухудшении guardrail-метрики.
- Продление после запуска без новой предрегистрации запрещено.

## 9. Проверки перед анализом

1. SRM: хи-квадрат против 50/50, p < 0.001 — анализ не проводится, ищется причина.
2. Баланс ковариат, известных до назначения: платформа, страна, источник трафика. Стандартизованная разница по каждой категории < 0.1. Превышение — расследование рандомизации до анализа.

## 10. Экономика и критерий решения

Точка безубыточности за 12 месяцев:

- затраты: 4 + 2 = 6 млн ₽;
- нужная дополнительная выручка: 6 / 0.30 = 20 млн ₽;
- новых пользователей за год: 6000 × 365 = 2 190 000;
- безубыточный прирост ARPU: 20 000 000 / 2 190 000 ≈ **+9.13 ₽ на пользователя** (3.65% от базовых 250 ₽);
- эквивалент при неизменном среднем чеке: 9.13 / 2500 ≈ **+0.37 п.п. конверсии** (10% → 10.37%).

Допущения: после внедрения новую страницу видят все новые пользователи; учитывается только выручка первых 7 дней; без дисконтирования; эффект на уже существующих пользователей не учитывается. Оценка консервативная.

Безубыточный эффект (0.37 п.п.) меньше MDE (0.5 п.п.): эффект между ними окупается, но тест обнаружит его с мощностью около 57%. Это сознательный компромисс по длительности, принятый до запуска.

Внедряем, если выполнены все условия:

1. основная метрика значимо выросла (p < 0.05, двусторонний тест);
2. точечная оценка прироста ARPU за 7 дней выше 9.13 ₽;
3. ни одна guardrail-метрика значимо не ухудшилась.

Иначе:

- **не внедрять** — эффект незначим или отрицателен;
- **доработать** — эффект положительный, но ниже безубыточности, или ухудшился guardrail; новая версия идёт в новый эксперимент;
- **продлить текущий тест нельзя** — более длинный тест требует новой предрегистрации и новой выборки.
